# Corrections and feedback

Feedback must be reviewed and submitted by a person using their own GitHub account. Automated issue creation and agent submissions are not accepted. Please use the issue forms linked from the website, especially when a work has missing or conflicting information.

For a work correction, keep the work ID and provide a public source URL, the proposed correction, and an explanation of the evidence. Separate a confirmed measurement or identity from a plausible estimate. Do not upload source photographs, scans, private collection details, or personal information.

The website opens GitHub's form for the visitor to review and submit. It contains no write token and does not create issues automatically. GitHub sign-in, a required personal-submission checkbox, and automatic closure of recognized bot accounts provide friction against automated feedback. These controls cannot prove that an account is operated by a person or prevent every agent using a human account. Stronger bot screening would require a separately configured server-side verification service.

Code contributions should preserve the distinction between catalogue facts, inferred attributes, and estimates. Keep sources and unknowns explicit. A shared title is not proof of a shared physical identity.
